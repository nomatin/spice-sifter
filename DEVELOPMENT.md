# Устройство и проверка DBUR Test

Подробные сведения о реализации, совместимости и результатах разработки. Краткий отчёт — [VERIFICATION.md](VERIFICATION.md).

# Подробности реализации

Утилита для проверки SPICE-схем через Altium MixedSim. Windows, Python 3.11+, только стандартная библиотека. Реальный сквозной сценарий подтверждён на Altium Designer **24.4.1.13**, Python 3.14.5, 30.10.2026.

## Запуск

```powershell
python dbur_test.py examples/divider.json
python dbur_test.py examples/diode.json --keep-files
python dbur_test.py examples/divider.json --altium "C:\Program Files\Altium\AD24\X2.EXE" --timeout 120
```

Путь: `--altium`, переменная `DBUR_ALTIUM`, затем стандартный `Program Files/Altium/AD24/X2.EXE` с проверкой версии 24.4. При явном указании версии отвечает пользователь. Нужен работоспособный и лицензированный Altium без блокирующих диалогов. Холодный запуск без ручного закрытия предупреждений пока не подтверждён: установленный Altium показывал ошибку Vault Explorer. В уже открытом Altium цикл автоматический.

stdout содержит один компактный JSON; коды завершения: PASS=0, FAIL=1, ERROR=2. `--verbose` выводит путь запуска в stderr, не нарушая JSON в stdout. При сохранении артефактов поле `diagnostics` содержит статус, признак выполнения скрипта и список файлов. `--keep-files` сохраняет их, при ошибках выполнения они также сохраняются автоматически.

## Вход

Обязательны `name`, полный `spice` (первая строка — заголовок), непустой `checks`. Анализ MVP — `.TRAN`. Проверка содержит `signal`, `measurement` (`first`, `last`, `min`, `max`), конечные включительные границы `min`/`max`. Названия сигналов сопоставляются без учёта регистра, неоднозначность отклоняется. Ошибки проверок имеют приоритет над FAIL; выполняются все проверки.

`models` — массив файлов относительно входного JSON. Вставляются абсолютные `.include` после заголовка. Кириллические пути подключаются через короткие имена Windows; если они отключены, выдаётся INPUT_INVALID с объяснением. Содержимое файлов моделей не изменяется. Вложенные относительные include в моделях и кириллические директивы, вручную записанные в `spice`, отдельно не проверены.

## Выполнение

Каждый запуск получает уникальный `%TEMP%/DBUR-Test/<id>`. Генерируется отдельный ASCII DelphiScript без BOM с процедурой RunTests. Через `X2.EXE -RScriptingSystem:RunScriptFile(...)` открывается свободный NSX, запускается `ADVSIM:RunSimulator`, проверяется точное имя текущего SDF и сохраняется только документ этого запуска. Для сохранения допускается ровно один дополнительный скрипт после возврата MixedSim. Завершение подтверждается служебным файлом, не кодом выхода X2. Скрипт сначала пишет временный статус, затем публикует его переименованием. SAVE_PENDING не считается завершением; окончательные состояния — OK или ERROR.

Нет проектов, постоянных компонентов, серверов, сторонних симуляторов, MCP-зависимости или эмуляции ввода. Пользовательские документы не сохраняются и не закрываются. Результат предыдущего запуска не используется. Параллельные вызовы DBUR блокируются файловой блокировкой. Не запускайте другую симуляцию вручную одновременно.

После тайм-аута Altium не завершается. Сохраняется `pending-run.txt`; следующий вызов возвращает BUSY до появления статуса предыдущего запуска. Если скрипт так и не завершился, после ручной проверки отсутствия активной симуляции удалите этот файл из `%TEMP%/DBUR-Test`. Если за отведённое время скрипт даже не начал исполняться, код ошибки SCRIPT_NOT_EXECUTED; если начал, но не завершился — TIMEOUT. Время запуска/работы Altium ограничено --timeout; определение версии выполняется отдельно (до 10 секунд).

## SDF и проверка

Собственный парсер SDF 1.0 читает текстовые записи и интерливированные пары X/Y float64, пропускает соответствующие вспомогательные float32 с проверкой границ. Поддерживает несколько Chart/Wave, проверяет размеры блоков и суммарный TotalPoints, не ищет текстовые маркеры внутри бинарных данных. Для CLI требуется ровно один Chart `Transient Analysis`. Неизвестные версии и комплексные бинарные данные отклоняются; структура SDFWave предусматривает комплексные значения для будущего расширения.

```powershell
python -m unittest discover -s tests -v
```

18 автоматических тестов: синтетические данные, повреждения/обрезания, несколько Chart/Wave, отказ для неподтверждённого комплексного формата, реальные данные делителя, Validator, неверный вход, тайм-аут и защита BUSY. Реальный SDF из 24.4 включён в tests/fixtures/divider_ad24_4.sdf (1008 точек, v(out)=2.5).

Результаты реальных запусков:

| Проверка | Результат |
|---|---|
| Делитель 2.49–2.51 В | PASS, 2.5 В |
| Делитель 3.0–3.2 В | FAIL, код 1 |
| v(unknown) | ERROR / SIGNAL_NOT_FOUND |
| Повторный запуск | PASS, отдельный каталог |
| Диод с внешней моделью | PASS, 0.6928681429973097 В |
| Кириллица и пробелы в пути модели | PASS через короткое имя Windows |
| Неопределённая SPICE-модель | ERROR / SIM_NOT_RUN |
| Тайм-аут и BUSY | Автотест с имитацией неотвечающего процесса |

Актуальный полный отчёт: tests/acceptance_report.json. Повторить реальную приёмку: `python tests/acceptance.py` (нужен открытый Altium). Краткие результаты: VERIFICATION.md. Полная текстовая диагностика ошибок MixedSim из панели Altium пока не извлекается: сохраняются netlist, скрипт, команда и статус. .OP, .DC, .AC в CLI, комплексные данные и независимое восстановление после зависания не поддержаны. MVP предназначен для действительных результатов .TRAN. Комплексные данные отклоняются без попыток угадать неподтверждённую структуру; .OP допускается исходным ТЗ только после отдельного подтверждения и в эту версию не включён.

Справка по API: [запуск скриптов](https://www.altium.com/documentation/altium-designer/scripting/running-scripts), [IServerDocument и сохранение](https://www.altium.com/documentation/altium-dxp-developer/iserverdocument-interface).

## Проверка открытого Altium

Перед отправкой скрипта CLI проверяет наличие основного процесса выбранного X2.EXE по полному пути. Вспомогательные процессы с параметром `-R` не считаются открытым Altium. Если основной процесс отсутствует: `ERROR`, код `ALTIUM_NOT_RUNNING`, завершение 2. Автоматического запуска закрытого Altium нет. Если Windows не позволяет проверить процессы, возвращается `ALTIUM_STATE_UNKNOWN`. Проверка наличия процесса не гарантирует, что приложение отвечает или не показывает модальный диалог. Проверка покрыта автоматическими тестами.
